# 5. Autoloads ធៀបនឹង Nodes ធម្មតា

Godot ផ្តល់មុខងារ **Autoload** ដើម្បីផ្ទុក Nodes ដោយស្វ័យប្រវត្តិនៅឫសគល់ (root) នៃគម្រោង ដែលអនុញ្ញាតឱ្យអ្នកចូលប្រើវាបានគ្រប់ទីកន្លែង (Global Access) ដូចជា Singleton។ តើអាចស្វែងយល់បន្ថែមនៅទីនេះ៖ [Singletons (Autoload)](https://docs.godotengine.org/en/stable/tutorials/scripting/singletons_autoload.html#doc-singletons-autoload)

> 💡 **ចំណាំ៖** Nodes ដែលបានផ្ទុកដោយស្វ័យប្រវត្តិ (Autoloaded nodes) **នឹងមិនត្រូវបានលុបចោល** នៅពេលអ្នកផ្លាស់ប្តូរ Scene តាមរយៈកូដដោយប្រើ [`SceneTree.change_scene_to_file()`](https://docs.godotengine.org/en/stable/classes/class_scenetree.html#class-scenetree-method-change-scene-to-file) នោះទេ។

នៅក្នុងមគ្គុទ្ទេសក៍នេះ អ្នកនឹងរៀន៖
- ✅ ពេលណាដែលគួរប្រើ Autoload
- ✅ បច្ចេកទេសដើម្បីជៀសវាងការប្រើ Autoload ដោយមិនចាំបាច់

---

## 🔊 បញ្ហា "សំឡេងកាត់" (The Cutting Audio Issue)

ម៉ាស៊ីនហ្គេម (Game Engines) មួយចំនួនអាចលើកទឹកចិត្តឱ្យប្រើ **Manager Classes** ឬ **Singletons** ដើម្បីរៀបចំមុខងារជាច្រើនទៅក្នុងវត្ថុតែមួយដែលអាចចូលប្រើបានគ្រប់ទីកន្លែង។ ប៉ុន្តែ Godot ផ្តល់វិធីជាច្រើនដើម្បីជៀសវាង **Global State** តាមរយៈ **Node Tree** និង **Signals**។

### 🎮 ឧទាហរណ៍ជាក់ស្តែង

ឧបមាថាយើងកំពុងសាងសង់ហ្គេម **Platformer** ហើយចង់ឱ្យមានសំឡេងនៅពេលអ្នកលេងប្រមូលកាក់។ យើងអាចប្រើ [`AudioStreamPlayer`](https://docs.godotengine.org/en/stable/classes/class_audiostreamplayer.html#class-audiostreamplayer)។

ប៉ុន្តែ ប្រសិនបើយើងហៅ `AudioStreamPlayer` ខណៈដែលវាកំពុងលេងសំឡេងរួចហើយ → **សំឡេងថ្មីនឹងកាត់សំឡេងចាស់ភ្លាមៗ** ❌

### ⚙️ ដំណោះស្រាយដំបូង៖ ប្រើ Sound Manager (Autoload)

យើងអាចសរសេរ `Sound` class ដែលជា Autoload ដើម្បី៖
- បង្កើត **Pool** នៃ `AudioStreamPlayer` nodes
- វិលជុំ (cycle) តាមតម្រូវការនៅពេលមានសំណើសំឡេងថ្មីៗ

```gdscript
# ឧទាហរណ៍នៃការហៅប្រើ
Sound.play("coin_pickup.ogg")
```

វិធីនេះដោះស្រាយបញ្ហាបានភ្លាមៗ ប៉ុន្តែអាចបង្ក **បញ្ហាធំៗចំនួន ៣**៖

| បញ្ហា | ការពិពណ៌នា |
|--------|-------------|
| 🌍 **Global State** | វត្ថុតែមួយ (`Sound`) ទទួលខុសត្រូវលើទិន្នន័យទាំងអស់។ ប្រសិនបើវាមានកំហុស ឬអស់ `AudioStreamPlayer` ក្នុង pool → nodes ទាំងអស់ដែលហៅវានឹងខូច។ |
| 🔓 **Global Access** | វត្ថុណាមួយអាចហៅ `Sound.play()` ពីទីកន្លែងណាក៏បាន → ពិបាករកប្រភពកំហុស (debug)។ |
| 💾 **Global Resource Allocation** | ការកំណត់ pool ទុកជាមុនអាចធ្វើឱ្យ៖ <br>• តិចពេក → មានកំហុស <br>• ច្រើនពេក → ចំណាយអង្គចងចាំ (memory) ច្រើនជាងការចាំបាច់ |

> ⚠️ **ចំណាំសំខាន់៖** ជាមួយ **Global Access** កូដណាមួយនៅទីកន្លែងណាក៏ដោយអាចផ្ញើទិន្នន័យខុសទៅ `Sound` autoload។ ដូច្នេះ ការស្វែងរក និងជួសជុលកំហុសអាចត្រូវការពិនិត្យ **គម្រោងទាំងមូល**។

### ✅ ដំណោះស្រាយល្អជាង៖ រក្សា AudioStreamPlayer ក្នុង Scene

ជំនួសឱ្យការប្រើ Autoload យើងអាចឱ្យ **Scene នីមួយៗ** រក្សា `AudioStreamPlayer` nodes ផ្ទាល់ខ្លួនតាមតម្រូវការ។ វិធីនេះជួយដោះស្រាយបញ្ហាទាំង ៣ ខាងលើ៖

1. 🧩 **រាល់ Scene គ្រប់គ្រងស្ថានភាព (state) ផ្ទាល់ខ្លួន** → បញ្ហាមួយកើតឡើងតែក្នុង Scene នោះប៉ុណ្ណោះ។
2. 🔍 **រាល់ Scene ចូលប្រើតែ nodes របស់ខ្លួន** → ងាយស្រួលរកឃើញថា node មួយណាជាអ្នកបង្កកំហុស។
3. 🎯 **រាល់ Scene បែងចែកធនធានតាមតម្រូវការពិតប្រាកដ** → មិនចំណាយ memory ច្រើនជាងការចាំបាច់។

## 📦 ការគ្រប់គ្រងមុខងារ ឬទិន្នន័យដែលចែករំលែក

មូលហេតុមួយទៀតដែលអ្នកអាចចង់ប្រើ Autoload គឺដើម្បី **ប្រើប្រាស់មុខងារ ឬទិន្នន័យដដែល** នៅទូទាំង Scenes ជាច្រើន។

### 🔧 ក្នុងករណីអនុគមន៍ (Functions)

អ្នកអាចបង្កើតប្រភេទថ្មីនៃ `Node` ដែលផ្តល់មុខងារនោះសម្រាប់ Scene តែមួយ ដោយប្រើពាក្យគន្លឹះ [`class_name`](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/gdscript_basics.html#doc-gdscript-basics-class-name) ក្នុង GDScript៖

```gdscript
# helper_functions.gd
class_name HelperFunctions
extends Node

static func calculate_score(base: int, multiplier: float) -> int:
    return int(base * multiplier)
```

### 💾 ក្នុងករណីទិន្នន័យ (Data)

អ្នកមានជម្រើសពីរ៖

1. **បង្កើតប្រភេទថ្មីនៃ [`Resource`](https://docs.godotengine.org/en/stable/classes/class_resource.html#class-resource)** ដើម្បីចែករំលែកទិន្នន័យ៖
   ```gdscript
   # game_data.gd
   class_name GameData
   extends Resource
   
   @export var player_name: String = ""
   @export var score: int = 0
   ```

2. **រក្សាទុកទិន្នន័យនៅក្នុងវត្ថុដែល Nodes ទាំងអស់អាចចូលប្រើបាន** ឧទាហរណ៍៖ ប្រើលក្ខណៈសម្បត្តិ `owner` ដើម្បីចូលប្រើ Root Node នៃ Scene៖
   ```gdscript
   var root = get_tree().current_scene
   var shared_data = root.get_node("SharedData")
   ```

## 🎯 ពេលណាដែលអ្នកគួរប្រើ Autoload?

### ✨ ជម្រើសដែលមិនត្រូវការ Autoload

GDScript គាំទ្រការបង្កើត **`static` functions** ដោយប្រើ `static func`។ ពេលប្រើជាមួយ `class_name` អ្នកអាចបង្កើត **Library** នៃ helper functions ដោយមិនចាំបាច់បង្កើត instance៖

```gdscript
# math_utils.gd
class_name MathUtils

static func clamp_value(value: float, min: float, max: float) -> float:
    return max(min, min(value, max))
```

> ⚠️ **ដែនកំណត់៖** `static func` មិនអាចយោងទៅលើ **member variables**, **non-static functions** ឬ **`self`** បានទេ។

ចាប់តាំងពី **Godot 4.1** មក GDScript ក៏គាំទ្រ **`static var`** ផងដែរ៖

```gdscript
class_name GlobalConfig
extends Node

static var game_version: String = "1.0.0"
static var max_players: int = 4
```

នេះមានន័យថា អ្នកអាច **ចែករំលែកអថេរ** នៅទូទាំង instances នៃថ្នាក់មួយ ដោយមិនចាំបាច់បង្កើត Autoload ដាច់ដោយឡែក។

### ✅ ពេលដែល Autoload ពិតជាមានប្រយោជន៍

Autoloaded nodes អាចធ្វើឱ្យកូដរបស់អ្នក **សាមញ្ញ និងមានរបៀបរៀបរយ** សម្រាប់ប្រព័ន្ធដែលមាន **វិសាលភាពធំទូលាយ** (broad scope)។

ប្រសិនបើ Autoload៖
- ✅ គ្រប់គ្រងព័ត៌មានផ្ទាល់ខ្លួនរបស់វា
- ✅ មិនលុកលុយ ឬកែប្រែទិន្នន័យរបស់ objects ផ្សេងៗ
- ✅ ដោះស្រាយកិច្ចការដែលត្រូវការការចូលប្រើគ្រប់ទីកន្លែង

→ នោះវាជាជម្រើសដ៏ល្អ! 🎉

#### ឧទាហរណ៍នៃប្រព័ន្ធគួរប្រើ Autoload៖

| ប្រព័ន្ធ | មូលហេតុ |
|----------|----------|
| 🗂️ **ប្រព័ន្ធភារកិច្ច (Quest System)** | ត្រូវការចូលប្រើទិន្នន័យភារកិច្ចពីគ្រប់ Scenes |
| 💬 **ប្រព័ន្ធសន្ទនា (Dialogue System)** | ត្រូវការរក្សាស្ថានភាពសន្ទនា និងជម្រើសអ្នកលេង |
| ⚙️ **ប្រព័ន្ធកំណត់ (Settings/Options)** | ត្រូវការរក្សាទុកការកំណត់អ្នកលេងគ្រប់ពេល |
| 🎵 **ប្រព័ន្ធគ្រប់គ្រងសំឡេងកម្រិតខ្ពស់** | ត្រូវការគ្រប់គ្រង volume, mute, និង audio bus ជាសកល |

## ⚠️ ចំណាំសំខាន់៖ Autoload ≠ Singleton

> ❗ **Autoload *មិនមែន* ជា Singleton ជានិច្ចនោះទេ!**

- គ្មានអ្វីការពារអ្នកពីការបង្កើត **ច្បាប់ចម្លង (copies)** នៃ node ដែលបានផ្ទុកដោយស្វ័យប្រវត្តិនោះទេ។
- Autoload គ្រាន់តែជា **ឧបករណ៍** ដែលធ្វើឱ្យ node មួយផ្ទុកដោយស្វ័យប្រវត្តិជាកូន (child) នៃ **Root** នៃ Scene Tree របស់អ្នក។
- វានឹងនៅតែមាន ទោះបីជាអ្នកដំណើរការ Scene ណាក៏ដោយ (ឧទាហរណ៍៖ ចុច F6)។

### 🔍 របៀបចូលប្រើ Autoload Node

អ្នកអាចទទួលបាន node ដែលបានផ្ទុកដោយស្វ័យប្រវត្តិ ដោយប្រើ៖

```gdscript
# ឧទាហរណ៍៖ Autoload ឈ្មោះ "Sound"
var sound_node = get_node("/root/Sound")
sound_node.play("coin_pickup.ogg")

# ឬ ប្រើ get_tree() ប្រសិនបើអ្នកចង់បានវិធីទូទៅជាង
var sound_node = get_tree().root.get_node("Sound")
```
