# 12.ប្រព័ន្ធគ្រប់គ្រងកំណែ

### ប្រព័ន្ធគ្រប់គ្រងកំណែ — Version control systems

### ការណែនាំ

Godot មានគោលដៅក្នុងការគាំទ្រ VCS និងបង្កើតឯកសារដែលអាចអានបាន និងអាចបញ្ចូលគ្នាបានភាគច្រើន។

### កម្មវិធីជំនួយប្រព័ន្ធគ្រប់គ្រងកំណែ[](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html#version-control-plugins)

Godot ក៏គាំទ្រការប្រើប្រាស់ប្រព័ន្ធគ្រប់គ្រងកំណែនៅក្នុងកម្មវិធីនិពន្ធផ្ទាល់ផងដែរ។ ទោះយ៉ាងណាក៏ដោយ ការគ្រប់គ្រងកំណែនៅក្នុងកម្មវិធីនិពន្ធទាមទារឱ្យមានកម្មវិធីជំនួយសម្រាប់ VCS ជាក់លាក់ដែលអ្នកកំពុងប្រើ។

គិតត្រឹមខែតុលា ឆ្នាំ 2025 មានតែកម្មវិធីជំនួយ Git ប៉ុណ្ណោះដែលមាន ប៉ុន្តែសហគមន៍អាចបង្កើតកម្មវិធីជំនួយ VCS បន្ថែមទៀត។

#### កម្មវិធីជំនួយ Git ផ្លូវការ[](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html#official-git-plugin)

ការប្រើប្រាស់ Git ពីខាងក្នុងកម្មវិធីនិពន្ធត្រូវបានគាំទ្រដោយកម្មវិធីជំនួយផ្លូវការ។ អ្នកអាចរកមើលការចេញផ្សាយថ្មីៗបំផុតនៅលើ [GitHub](https://github.com/godotengine/godot-git-plugin/releases)។

ឯកសារណែនាំអំពីរបៀបប្រើប្រាស់កម្មវិធីជំនួយ Git អាចរកមើលបាននៅលើ [wiki](https://github.com/godotengine/godot-git-plugin/wiki) របស់វា។

### ឯកសារដែលត្រូវដកចេញពី VCS[](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html#files-to-exclude-from-vcs)

> ចំណាំ
>
> នេះគឺជាបញ្ជីឯកសារ និងថតដែលគួរតែមិនអើពើពីការគ្រប់គ្រងកំណែនៅក្នុង Godot 4.1 និងកំណែក្រោយៗ។
>
> បញ្ជីឯកសារ និងថតដែលគួរតែមិនអើពើពីការគ្រប់គ្រងកំណែនៅក្នុង Godot 3.x និង Godot 4.0 គឺ **ខុសគ្នាទាំងស្រុង**។ នេះមានសារៈសំខាន់ ព្រោះ Godot 3.x និង 4.0 អាចរក្សទុកព័ត៌មានសម្ងាត់ដែលងាយរងគ្រោះនៅក្នុង `export_presets.cfg` (ខុសពី Godot 4.1 និងកំណែក្រោយៗ)។
>
> ប្រសិនបើអ្នកកំពុងប្រើ Godot 3 សូមពិនិត្យមើលកំណែ `3.6` នៃទំព័រឯកសារនេះជំនួសវិញ។

មានឯកសារ និងថតមួយចំនួនដែល Godot បង្កើតដោយស្វ័យប្រវត្តិនៅពេលបើកគម្រោងនៅក្នុងកម្មវិធីនិពន្ធជាលើកដំបូង។ ដើម្បីជៀសវាងការធ្វើឱ្យឃ្លាំងគ្រប់គ្រងកំណែរបស់អ្នកមានទិន្នន័យដែលបង្កើតឡើងច្រើនពេក អ្នកគួរតែបន្ថែមវាទៅក្នុងការមិនអើពើរបស់ VCS របស់អ្នក៖

* `.godot/`: ថតនេះរក្សទុកទិន្នន័យ cache គម្រោងផ្សេងៗ។
* `*.translation`: ឯកសារទាំងនេះគឺជា [ការបកប្រែ](https://docs.godotengine.org/en/stable/tutorials/i18n/internationalizing_games.html#doc-internationalizing-games) ដែលនាំចូលជាទម្រង់ binary ដែលបង្កើតពីឯកសារ CSV។

អ្នកអាចធ្វើឱ្យកម្មវិធីគ្រប់គ្រងគម្រោង Godot បង្កើតមេតាដាតាគ្រប់គ្រងកំណែសម្រាប់អ្នកដោយស្វ័យប្រវត្តិនៅពេលបង្កើតគម្រោង។ នៅពេលជ្រើសរើសជម្រើស **Git** វានឹងបង្កើតឯកសារ `.gitignore` និង `.gitattributes` នៅក្នុងឫសគម្រោង៖

![ការបង្កើតមេតាដាតាគ្រប់គ្រងកំណែនៅក្នុងប្រអប់បង្កើតគម្រោងថ្មីរបស់កម្មវិធីគ្រប់គ្រងគម្រោង](https://docs.godotengine.org/en/stable/_images/version_control_systems_generate_metadata.webp)

ការបង្កើតមេតាដាតាគ្រប់គ្រងកំណែនៅក្នុងប្រអប់ **គម្រោងថ្មី** របស់កម្មវិធីគ្រប់គ្រងគម្រោង[](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html#id1)

នៅក្នុងគម្រោងដែលមានស្រាប់ សូមជ្រើសរើសម៉ឺនុយ **Project** នៅផ្នែកខាងលើនៃកម្មវិធីនិពន្ធ បន្ទាប់មកជ្រើសរើស **Version Control > Generate Version Control Metadata**។ នេះនឹងបង្កើតឯកសារដូចគ្នា ដូចជាការអនុវត្តប្រតិបត្តិការនៅក្នុងកម្មវិធីគ្រប់គ្រងគម្រោង។

### ការធ្វើការជាមួយ Git នៅលើ Windows[](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html#working-with-git-on-windows)

អតិថិជន Git for Windows ភាគច្រើនត្រូវបានកំណត់រចនាសម្ព័ន្ធដោយមាន `core.autocrlf` កំណត់តម្លៃជា `true`។ នេះអាចនាំឱ្យឯកសារត្រូវបានសម្គាល់ថាត្រូវបានកែប្រែដោយ Git ដោយមិនចាំបាច់ ដោយសារតែការបញ្ចប់បន្ទាត់របស់វាត្រូវបានបម្លែងពី LF ទៅ CRLF ដោយស្វ័យប្រវត្តិ។

វាប្រសើរជាងក្នុងការកំណត់ជម្រើសនេះជា៖

```bash
git config --global core.autocrlf input
```

ការបង្កើតមេតាដាតាគ្រប់គ្រងកំណែដោយប្រើកម្មវិធីគ្រប់គ្រងគម្រោង ឬកម្មវិធីនិពន្ធនឹងអនុវត្តការបញ្ចប់បន្ទាត់ LF ដោយស្វ័យប្រវត្តិដោយប្រើឯកសារ `.gitattributes`។ ក្នុងករណីនេះ អ្នកមិនចាំបាច់ផ្លាស់ប្តូរការកំណត់រចនាសម្ព័ន្ធ Git របស់អ្នកទេ។

### Git LFS[](https://docs.godotengine.org/en/stable/tutorials/best_practices/version_control_systems.html#git-lfs)

Git LFS (Large File Storage) គឺជាផ្នែកបន្ថែមរបស់ Git ដែលអនុញ្ញាតឱ្យអ្នកគ្រប់គ្រងឯកសារធំៗនៅក្នុងឃ្លាំងរបស់អ្នក។ វាជំនួសឯកសារធំៗដោយចង្អុលបង្ហាញជាអក្សរនៅខាងក្នុង Git ខណៈដែលរក្សាទុកខ្លឹមសារឯកសារនៅលើម៉ាស៊ីនបម្រើពីចម្ងាយ។ នេះមានប្រយោជន៍សម្រាប់ការគ្រប់គ្រងធនធានធំៗ ដូចជា textures ឯកសារសំឡេង និងម៉ូដែល 3D ដោយមិនធ្វើឱ្យឃ្លាំង Git របស់អ្នកមានទំហំធំពេក។

> ចំណាំ
>
> នៅពេលប្រើ Git LFS អ្នកនឹងចង់ប្រាកដថាវាត្រូវបានរៀបចំមុនពេលអ្នក commit ឯកសារណាមួយទៅក្នុងឃ្លាំងរបស់អ្នក។ ប្រសិនបើអ្នកបាន commit ឯកសារទៅក្នុងឃ្លាំងរបស់អ្នករួចហើយ អ្នកនឹងត្រូវយកវាចេញពីឃ្លាំង ហើយបន្ថែមវាម្តងទៀតបន្ទាប់ពីរៀបចំ Git LFS។
>
> វាអាចទៅរួចក្នុងការប្រើ `git lfs migrate` ដើម្បីបម្លែងឯកសារដែលមានស្រាប់នៅក្នុងឃ្លាំងរបស់អ្នក ប៉ុន្តែនេះគឺជាការងារដែលស៊ីជម្រៅជាង និងទាមទារការយល់ដឹងល្អអំពី Git។
>
> វិធីសាស្ត្រទូទៅមួយគឺការរៀបចំឃ្លាំងថ្មីជាមួយ Git LFS (និង `.gitattributes` ដែលត្រឹមត្រូវ) បន្ទាប់មកចម្លងឯកសារពីឃ្លាំងចាស់ទៅឃ្លាំងថ្មី។ តាមវិធីនេះ អ្នកអាចប្រាកដថាឯកសារទាំងអស់ត្រូវបានតាមដានដោយ LFS តាំងពីដំបូង។

ដើម្បីប្រើ Git LFS ជាមួយ Godot អ្នកត្រូវដំឡើងផ្នែកបន្ថែម Git LFS និងកំណត់រចនាសម្ព័ន្ធវាឱ្យតាមដានប្រភេទឯកសារដែលអ្នកចង់គ្រប់គ្រង។ អ្នកអាចធ្វើបែបនេះដោយដំណើរការពាក្យបញ្ជាខាងក្រោមនៅក្នុង terminal របស់អ្នក៖

```bash
git lfs install
```

នេះនឹងបង្កើតឯកសារ `.gitattributes` នៅក្នុងឃ្លាំងរបស់អ្នកដែលប្រាប់ Git ឱ្យប្រើ LFS សម្រាប់ប្រភេទឯកសារដែលបានបញ្ជាក់។ អ្នកអាចបន្ថែមប្រភេទឯកសារបន្ថែមទៀតដោយកែប្រែឯកសារ `.gitattributes`។ ឧទាហរណ៍ ដើម្បីតាមដានឯកសារ GLB ទាំងអស់ អ្នកអាចធ្វើបែបនេះដោយដំណើរការពាក្យបញ្ជាខាងក្រោមនៅក្នុង terminal របស់អ្នក៖

```bash
git lfs track "*.glb"
```

នៅពេលអ្នកបន្ថែម ឬកែប្រែឯកសារដែលត្រូវបានតាមដានដោយ LFS, Git នឹងរក្សទុកវានៅក្នុង LFS ដោយស្វ័យប្រវត្តិជំនួសឱ្យប្រវត្តិ Git ធម្មតា។ អ្នកអាច push និង pull ឯកសារ LFS ដូចជាឯកសារ Git ធម្មតាដែរ ប៉ុន្តែសូមចងចាំថាឯកសារ LFS ត្រូវបានរក្សទុកដាច់ដោយឡែកពីប្រវត្តិ Git ដែលនៅសល់របស់អ្នក។ នេះមានន័យថា អ្នកអាចនឹងត្រូវដំឡើង Git LFS នៅលើម៉ាស៊ីនណាមួយដែលអ្នក clone ឃ្លាំងទៅ ដើម្បីចូលប្រើឯកសារ LFS។

ខាងក្រោមនេះគឺជាឧទាហរណ៍ឯកសារ `.gitattributes` ដែលអ្នកអាចប្រើជាចំណុចចាប់ផ្តើមសម្រាប់ Git LFS។ ប្រភេទឯកសារទាំងនេះត្រូវបានជ្រើសរើសព្រោះវាត្រូវបានប្រើជាទូទៅ ប៉ុន្តែអ្នកអាចកែប្រែបញ្ជីដើម្បីបញ្ចូលប្រភេទ binary ណាមួយដែលអ្នកអាចមាននៅក្នុងគម្រោងរបស់អ្នក។
