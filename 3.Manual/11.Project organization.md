## ការរៀបចំគម្រោង — ឯកសារ Godot Engine (stable) ជាភាសាអង់គ្លេស

## សេចក្តីផ្តើម[](https://docs.godotengine.org/en/stable/tutorials/best_practices/project_organization.html#introduction "Link to this heading")

ដោយសារ Godot មិនមានការកំណត់ណាមួយលើរចនាសម្ព័ន្ធគម្រោង ឬការប្រើប្រាស់ប្រព័ន្ធឯកសារនោះទេ ការរៀបចំឯកសារនៅពេលរៀនអំពី engine នេះអាចហាក់ដូចជាពិបាក។ មេរៀននេះស្នើឡើងនូវដំណើរការមួយដែលគួរតែជាចំណុចចាប់ផ្តើមដ៏ល្អ។ យើងក៏នឹងលើកឡើងអំពីការប្រើប្រាស់ version control ជាមួយ Godot ផងដែរ។

## ការរៀបចំ[](https://docs.godotengine.org/en/stable/tutorials/best_practices/project_organization.html#organization "Link to this heading")

Godot មានលក្ខណៈផ្អែកលើ scene ជាចម្បង ហើយប្រើប្រាស់ប្រព័ន្ធឯកសារតាមដែលមាន ដោយគ្មាន metadata ឬមូលដ្ឋានទិន្នន័យធនធានណាមួយឡើយ។

ផ្ទុយពី engine ផ្សេងៗទៀត ធនធានជាច្រើនត្រូវបានផ្ទុកនៅក្នុង scene ខ្លួនឯង ដូច្នេះចំនួនឯកសារនៅក្នុងប្រព័ន្ធឯកសារគឺទាបជាងយ៉ាងច្រើន។

ដោយគិតគូរពីចំណុចនេះ វិធីសាស្ត្រដែលគេប្រើជាទូទៅបំផុតគឺការដាក់ធនធានជាក្រុមឱ្យនៅជិតនឹង scene តាមដែលអាចធ្វើទៅបាន; នៅពេលដែលគម្រោងមួយកាន់តែធំ វាធ្វើឱ្យវាកាន់តែងាយស្រួលក្នុងការថែរក្សា។

ជាឧទាហរណ៍ គេអាចដាក់ធនធានមូលដ្ឋានរបស់គេ ដូចជា រូបភាព sprite, mesh គំរូ 3D, materials, និងតន្ត្រី ជាដើម ទៅក្នុងថតតែមួយ។ បន្ទាប់មក គេអាចប្រើថតដាច់ដោយឡែកមួយទៀតដើម្បីផ្ទុកកម្រិតដែលបានសាងសង់ឡើងដែលប្រើធនធានទាំងនោះ។

```
/project.godot
/docs/.gdignore  # See "Ignoring specific folders" below
/docs/learning.html
/models/town/house/house.dae
/models/town/house/window.png
/models/town/house/door.png
/characters/player/cubio.dae
/characters/player/cubio.png
/characters/enemies/goblin/goblin.dae
/characters/enemies/goblin/goblin.png
/characters/npcs/suzanne/suzanne.dae
/characters/npcs/suzanne/suzanne.png
/levels/riverdale/riverdale.scn
```

## ការណែនាំអំពីរចនាប័ទ្ម[](https://docs.godotengine.org/en/stable/tutorials/best_practices/project_organization.html#style-guide "Link to this heading")

ដើម្បីឱ្យមានភាពស៊ីសង្វាក់គ្នានៅពាសពេញគម្រោងផ្សេងៗ យើងណែនាំឱ្យអនុវត្តតាមការណែនាំទាំងនេះ៖

-   ប្រើ **snake_case** សម្រាប់ឈ្មោះថត និងឈ្មោះឯកសារ (លើកលែងតែស្គ្រីប C#)។ វិធីនេះជួយជៀសវាងបញ្ហាអំពីភាពខុសគ្នារវាងអក្សរធំ-តូចដែលអាចកើតឡើងបន្ទាប់ពី export គម្រោងនៅលើ Windows។ ស្គ្រីប C# គឺជាករណីលើកលែងពីច្បាប់នេះ ព្រោះការអនុវត្តគឺត្រូវដាក់ឈ្មោះវាតាមឈ្មោះ class ដែលគួរតែស្ថិតក្នុងទម្រង់ PascalCase។
    
-   ប្រើ **PascalCase** សម្រាប់ឈ្មោះ node ព្រោះវាត្រូវគ្នានឹងការដាក់ឈ្មោះ node ដែលមានស្រាប់ក្នុង engine។
    
-   ជាទូទៅ ត្រូវរក្សាធនធានពីភាគីទីបីនៅក្នុងថតកម្រិតខ្ពស់ `addons/` ទោះបីជាវាមិនមែនជា plugin របស់កម្មវិធីនិពន្ធក៏ដោយ។ វិធីនេះធ្វើឱ្យកាន់តែងាយស្រួលក្នុងការតាមដានថា តើឯកសារណាខ្លះមកពីភាគីទីបី។ មានករណីលើកលែងមួយចំនួនចំពោះច្បាប់នេះ; ឧទាហរណ៍ ប្រសិនបើអ្នកប្រើធនធានហ្គេមពីភាគីទីបីសម្រាប់តួអង្គមួយ វាសមហេតុផលជាងក្នុងការបញ្ចូលវានៅក្នុងថតតែមួយជាមួយនឹង scene និងស្គ្រីបរបស់តួអង្គនោះ។
    

## ការនាំចូល[](https://docs.godotengine.org/en/stable/tutorials/best_practices/project_organization.html#importing "Link to this heading")

Godot ជំនាន់មុន 3.0 បានធ្វើដំណើរការនាំចូលពីឯកសារដែលនៅខាងក្រៅគម្រោង។ ទោះបីជាការនេះអាចមានប្រយោជន៍នៅក្នុងគម្រោងធំៗក៏ដោយ ក៏វាបានបណ្តាលឱ្យមានការលំបាកក្នុងការរៀបចំសម្រាប់អ្នកអភិវឌ្ឍន៍ភាគច្រើន។

ដោយសារតែហេតុផលនេះ ឥឡូវនេះធនធានត្រូវបាននាំចូលដោយស្វ័យប្រវត្តិពីខាងក្នុងថតគម្រោង។

### ការមិនយកចិត្តទុកដាក់លើថតជាក់លាក់[](https://docs.godotengine.org/en/stable/tutorials/best_practices/project_organization.html#ignoring-specific-folders "Link to this heading")

ដើម្បីការពារកុំឱ្យ Godot នាំចូលឯកសារដែលមាននៅក្នុងថតជាក់លាក់មួយ សូមបង្កើតឯកសារទទេមួយដែលមានឈ្មោះថា `.gdignore` នៅក្នុងថតនោះ (ត្រូវការមាន `.` នៅខាងដើម)។ វិធីនេះអាចមានប្រយោជន៍ដើម្បីបង្កើនល្បឿនក្នុងការនាំចូលគម្រោងដំបូង។

> **ចំណាំ**
> 
> ដើម្បីបង្កើតឯកសារដែលឈ្មោះចាប់ផ្តើមដោយចុច `.` នៅលើ Windows សូមដាក់ចុច `.` នៅទាំងដើម និងចុងនៃឈ្មោះឯកសារ (".gdignore.")។ Windows នឹងលុបចុច `.` នៅចុងចោលដោយស្វ័យប្រវត្តិ នៅពេលអ្នកបញ្ជាក់ឈ្មោះ។
> 
> ជម្រើសមួយទៀត អ្នកអាចប្រើកម្មវិធីនិពន្ធអត្ថបទដូចជា Notepad++ ឬប្រើពាក្យបញ្ជាខាងក្រោមនៅក្នុង command prompt៖ `type nul > .gdignore`

នៅពេលដែលថតត្រូវបានមិនយកចិត្តទុកដាក់ ធនធាននៅក្នុងថតនោះនឹងមិនអាចផ្ទុកបានទៀតទេដោយប្រើវិធីសាស្ត្រ `load()` និង `preload()`។ ការមិនយកចិត្តទុកដាក់លើថតក៏នឹងលាក់វាដោយស្វ័យប្រវត្តិពី FileSystem dock ផងដែរ ដែលអាចមានប្រយោជន៍ដើម្បីកាត់បន្ថយភាពច្របូកច្របល់។

សូមចំណាំថា ខ្លឹមសាររបស់ឯកសារ `.gdignore` ត្រូវបានមិនយកចិត្តទុកដាក់ ដែលជាមូលហេតុថាហេតុអ្វីបានជាឯកសារនេះគួរតែទទេ។ វាមិនគាំទ្រលំនាំដូចឯកសារ `.gitignore` ធ្វើនោះទេ។

## ភាពខុសគ្នារវាងអក្សរធំ-តូច[](https://docs.godotengine.org/en/stable/tutorials/best_practices/project_organization.html#case-sensitivity "Link to this heading")

Windows និងជំនាន់ថ្មីៗរបស់ macOS ប្រើប្រព័ន្ធឯកសារដែលមិនបែងចែកអក្សរធំ-តូចតាមលំនាំដើម ខណៈដែលការចែកចាយ Linux ប្រើប្រព័ន្ធឯកសារដែលបែងចែកអក្សរធំ-តូចតាមលំនាំដើម។ ចំណុចនេះអាចបណ្តាលឱ្យមានបញ្ហាបន្ទាប់ពី export គម្រោងមួយ ព្រោះប្រព័ន្ធឯកសារនិម្មិត PCK របស់ Godot គឺបែងចែកអក្សរធំ-តូច។ ដើម្បីជៀសវាងចំណុចនេះ វាត្រូវបានណែនាំឱ្យប្រើការដាក់ឈ្មោះ `snake_case` សម្រាប់ឯកសារទាំងអស់នៅក្នុងគម្រោង (និងអក្សរតូចជាទូទៅ)។

> **ចំណាំ**
> 
> អ្នកអាចបំពានច្បាប់នេះនៅពេលដែលការណែនាំអំពីរចនាប័ទ្មនិយាយផ្ទុយ (ដូចជាការណែនាំអំពីរចនាប័ទ្ម C#)។ ទោះយ៉ាងណាក៏ដោយ សូមមានភាពស៊ីសង្វាក់គ្នាដើម្បីជៀសវាងកំហុស។

នៅលើ Windows 10 ដើម្បីជៀសវាងកំហុសបន្ថែមទៀតដែលទាក់ទងនឹងភាពខុសគ្នារវាងអក្សរធំ-តូច អ្នកក៏អាចធ្វើឱ្យថតគម្រោងបែងចែកអក្សរធំ-តូចផងដែរ។ បន្ទាប់ពីបើកមុខងារ Windows Subsystem for Linux សូមដំណើរការពាក្យបញ្ជាខាងក្រោមនៅក្នុងបង្អួច PowerShell៖

```powershell
# To enable case-sensitivity:
fsutil file setcasesensitiveinfo <path to project folder> enable

# To disable case-sensitivity:
fsutil file setcasesensitiveinfo <path to project folder> disable
```

ប្រសិនបើអ្នកមិនទាន់បានបើក Windows Subsystem for Linux អ្នកអាចវាយបញ្ចូលបន្ទាត់ខាងក្រោមនៅក្នុងបង្អួច PowerShell *ដែលដំណើរការជា Administrator* បន្ទាប់មកចាប់ផ្តើមឡើងវិញនៅពេលដែលត្រូវបានស្នើឡើង៖

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Windows-Subsystem-Linux
```

> **ចំណាំ:** ទំព័រនេះមាន iframe(s) ចំនួន 1 ដែលមកពីប្រភពខុសគ្នា (cross-origin) ដែលមិនអាចចូលប្រើបានដោយសារគោលការណ៍សុវត្ថិភាពរបស់កម្មវិធីរុករក។ ខ្លឹមសារមួយចំនួនអាចនឹងបាត់។ តំណភ្ជាប់ទៅកាន់ iframe ទាំងនេះត្រូវបានរក្សាទុកនៅកន្លែងដែលអាចធ្វើទៅបាន។
