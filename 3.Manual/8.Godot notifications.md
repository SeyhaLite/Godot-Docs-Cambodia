
## ដំណឹងជូនក្នុង Godot — ឯកសារ Godot Engine (stable) ជាភាសាអង់គ្លេស

រាល់ [Object](https://docs.godotengine.org/en/stable/classes/class_object.html) ទាំងអស់ក្នុង Godot បានអនុវត្តអនុគមន៍ [\_notification](https://docs.godotengine.org/en/stable/classes/class_object.html#class-object-private-method-notification)។ គោលបំណងរបស់វាគឺដើម្បីអនុញ្ញាតឱ្យ Object ឆ្លើយតបទៅនឹងការហៅចូលកម្រិតអេនជីនផ្សេងៗដែលអាចទាក់ទងនឹងវា។ ឧទាហរណ៍ ប្រសិនបើអេនជីនប្រាប់ឱ្យ [CanvasItem](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html#class-canvasitem) "គូរ" វានឹងហៅ `_notification(NOTIFICATION_DRAW)`។

ការជូនដំណឹងមួយចំនួន ដូចជាការគូរ គឺមានប្រយោជន៍ក្នុងការសរសេរជាន់លើក្នុងស្គ្រីប។ ខ្លាំងណាស់ដែល Godot បានបង្ហាញជាច្រើនក្នុងចំណោមពួកវាជាមួយអនុគមន៍ដែលមានការកំណត់ជាក់លាក់៖

-   `_ready()`: `NOTIFICATION_READY`
    
-   `_enter_tree()`: `NOTIFICATION_ENTER_TREE`
    
-   `_exit_tree()`: `NOTIFICATION_EXIT_TREE`
    
-   `_process(delta)`: `NOTIFICATION_PROCESS`
    
-   `_physics_process(delta)`: `NOTIFICATION_PHYSICS_PROCESS`
    
-   `_draw()`: `NOTIFICATION_DRAW`
    

អ្វីដែលអ្នកប្រើប្រាស់ *អាចនឹងមិន* ដឹងនោះគឺការជូនដំណឹងមានសម្រាប់ប្រភេទផ្សេងទៀតក្រៅពី Node តែមួយមុខ ឧទាហរណ៍៖

-   [Object::NOTIFICATION\_POSTINITIALIZE](https://docs.godotengine.org/en/stable/classes/class_object.html#class-object-constant-notification-postinitialize): ការហៅចូលដែលបញ្ជាក់កំឡុងពេលការចាប់ផ្តើមដំណើរការរបស់ object។ មិនអាចចូលប្រើបានដោយស្គ្រីបទេ។
    
-   [Object::NOTIFICATION\_PREDELETE](https://docs.godotengine.org/en/stable/classes/class_object.html#class-object-constant-notification-predelete): ការហៅចូលដែលបញ្ជាក់មុនពេលអេនជីនលុប Object ចោល ពោលគឺជា "destructor"។
    

ហើយការហៅចូលជាច្រើនដែល *មាន* ក្នុង Nodes មិនមានវិធីសាស្រ្តដែលមានការកំណត់ជាក់លាក់ណាមួយទេ ប៉ុន្តែនៅតែមានប្រយោជន៍ខ្លាំងណាស់។

-   [Node::NOTIFICATION\_PARENTED](https://docs.godotengine.org/en/stable/classes/class_node.html#class-node-constant-notification-parented): ការហៅចូលដែលបញ្ជាក់គ្រប់ពេលដែលអ្នកបន្ថែម node កូនទៅ node មួយទៀត។
    
-   [Node::NOTIFICATION\_UNPARENTED](https://docs.godotengine.org/en/stable/classes/class_node.html#class-node-constant-notification-unparented): ការហៅចូលដែលបញ្ជាក់គ្រប់ពេលដែលអ្នកដក node កូនចេញពី node មួយទៀត។
    

អ្នកអាចចូលប្រើការជូនដំណឹងដែលបានកំណត់ផ្ទាល់ខ្លួនទាំងអស់នេះពីវិធីសាស្រ្ត `_notification()` ជាសកល។

> ចំណាំ
> 
> វិធីសាស្រ្តនៅក្នុងឯកសារដែលមានស្លាកថា "virtual" ក៏ត្រូវបានគេបង្កើតឡើងដើម្បីឱ្យស្គ្រីបសរសេរជាន់លើផងដែរ។

ឧទាហរណ៍បុរាណមួយគឺវិធីសាស្រ្ត [\_init](https://docs.godotengine.org/en/stable/classes/class_object.html#class-object-private-method-init) ក្នុង Object។ ខណៈដែលវាមិនមាន `NOTIFICATION_*` សមមូលទេ អេនជីននៅតែហៅវិធីសាស្រ្តនេះ។ ភាសាភាគច្រើន (លើកលែងតែ C#) ពឹងផ្អែកលើវាជាអ្នកសាងសង់ (constructor)។

ដូច្នេះ តើក្នុងស្ថានភាពណាដែលអ្នកគួរប្រើការជូនដំណឹង ឬអនុគមន៍ virtual មួយណាមួយក្នុងចំណោមទាំងនេះ?

## \_process ធៀបនឹង \_physics\_process ធៀបនឹង \*\_input[](https://docs.godotengine.org/en/stable/tutorials/best_practices/godot_notifications.html#process-vs-physics-process-vs-input "Link to this heading")

ប្រើ `_process()` នៅពេលដែលអ្នកត្រូវការពេលវេលា delta ដែលអាស្រ័យលើអត្រាបង្ហាញ (framerate) រវាងស៊ុមនីមួយៗ។ ប្រសិនបើកូដដែលធ្វើឱ្យទិន្នន័យវត្ថុទាន់សម័យត្រូវធ្វើបច្ចុប្បន្នភាពឱ្យបានញឹកញាប់តាមដែលអាចធ្វើទៅបាន នេះគឺជាទីតាំងត្រឹមត្រូវ។ ការត្រួតពិនិត្យលក្ខខណ្ឌដែលកើតឡើងម្តងហើយម្តងទៀត និងការដាក់ទិន្នន័យជា cache ជាញឹកញាប់ត្រូវបានអនុវត្តនៅទីនេះ ប៉ុន្តែវាអាស្រ័យលើប្រេកង់ដែលអ្នកត្រូវការឱ្យការវាយតម្លៃទាន់សម័យ។ ប្រសិនបើពួកវាមិនចាំបាច់អនុវត្តរាល់ស៊ុមទេ នោះការអនុវត្តរង្វិលជុំ Timer-timeout គឺជាជម្រើសមួយទៀត។

```gdscript
# Allows for recurring operations that don't trigger script logic
# every frame (or even every fixed frame).
func _ready():
	var timer = Timer.new()
	timer.autostart = true
	timer.wait_time = 0.5
	add_child(timer)
	timer.timeout.connect(func():
		print("This block runs every 0.5 seconds")
	)
```

ប្រើ `_physics_process()` នៅពេលដែលអ្នកត្រូវការពេលវេលា delta ដែលមិនអាស្រ័យលើអត្រាបង្ហាញ (framerate) រវាងស៊ុមនីមួយៗ។ ប្រសិនបើកូដត្រូវការការធ្វើបច្ចុប្បន្នភាពដែលមានភាពស៊ីសង្វាក់គ្នាតាមពេលវេលា ដោយមិនគិតពីថាពេលវេលាដើរលឿន ឬយឺតយ៉ាងណានោះទេ នេះគឺជាទីតាំងត្រឹមត្រូវ។ ប្រតិបត្តិការ kinematic និង object transform ដែលកើតឡើងម្តងហើយម្តងទៀតគួរតែអនុវត្តនៅទីនេះ។

ខណៈដែលវាអាចធ្វើទៅបាន ដើម្បីសម្រេចបាននូវដំណើរការល្អបំផុត អ្នកគួរជៀសវាងការធ្វើការត្រួតពិនិត្យ input ក្នុងអំឡុងពេលការហៅចូលទាំងនេះ។ `_process()` និង `_physics_process()` នឹងបញ្ជាក់នៅគ្រប់ឱកាស (ពួកវាមិន "សម្រាក" តាមលំនាំដើមទេ)។ ផ្ទុយទៅវិញ ការហៅចូល `*_input()` នឹងបញ្ជាក់តែនៅស៊ុមដែលអេនជីនបានរកឃើញ input ជាក់ស្តែងប៉ុណ្ណោះ។

អ្នកអាចត្រួតពិនិត្យសកម្មភាព input នៅក្នុងការហៅចូល input ដូចគ្នា។ ប្រសិនបើអ្នកចង់ប្រើពេលវេលា delta អ្នកអាចទាញយកវាពីវិធីសាស្រ្តពេលវេលា delta ដែលទាក់ទងតាមតម្រូវការ។

```gdscript
# Called every frame, even when the engine detects no input.
func _process(delta):
	if Input.is_action_just_pressed("ui_select"):
		print(delta)

# Called during every input event.
func _unhandled_input(event):
	match event.get_class():
		"InputEventKey":
			if Input.is_action_just_pressed("ui_accept"):
				print(get_process_delta_time())
```

## \_init ធៀបនឹងការចាប់ផ្តើមដំណើរការ ធៀបនឹង export[](https://docs.godotengine.org/en/stable/tutorials/best_practices/godot_notifications.html#init-vs-initialization-vs-export "Link to this heading")

ប្រសិនបើស្គ្រីបចាប់ផ្តើមដំណើរការ subtree របស់ node ផ្ទាល់ខ្លួន ដោយគ្មានឈុត (scene) នោះកូដនោះគួរតែអនុវត្តនៅក្នុង `_init()`។ ការចាប់ផ្តើមដំណើរការលក្ខណៈសម្បត្តិផ្សេងទៀត ឬការចាប់ផ្តើមដំណើរការដែលមិនអាស្រ័យលើ SceneTree ក៏គួរដំណើរការនៅទីនេះផងដែរ។

> ចំណាំ
> 
> សមមូល C# ចំពោះវិធីសាស្រ្ត `_init()` របស់ GDScript គឺជា constructor។

`_init()` បញ្ជាក់មុន `_enter_tree()` ឬ `_ready()` ប៉ុន្តែបន្ទាប់ពីស្គ្រីបបង្កើត និងចាប់ផ្តើមដំណើរការលក្ខណៈសម្បត្តិរបស់វារួចរាល់។ នៅពេលបង្កើតឈុត (instantiating a scene) តម្លៃលក្ខណៈសម្បត្តិនឹងត្រូវបានកំណត់ឡើងតាមលំដាប់លំដោយដូចខាងក្រោម៖

1.  **ការកំណត់តម្លៃដំបូង:** លក្ខណៈសម្បត្តិត្រូវបានកំណត់តម្លៃចាប់ផ្តើមរបស់វា ឬតម្លៃលំនាំដើមរបស់វា ប្រសិនបើមិនមានការកំណត់ណាមួយ។ ប្រសិនបើមាន setter វានឹងមិនត្រូវបានប្រើទេ។
    
2.  **ការកំណត់ `_init()`:** តម្លៃរបស់លក្ខណៈសម្បត្តិត្រូវបានជំនួសដោយការកំណត់ណាមួយដែលបានធ្វើឡើងក្នុង `_init()` ដែលបញ្ជាក់ setter។
    
3.  **ការកំណត់តម្លៃដែលបាន export:** តម្លៃរបស់លក្ខណៈសម្បត្តិដែលបាន export ត្រូវបានជំនួសម្តងទៀតដោយតម្លៃណាមួយដែលបានកំណត់នៅក្នុង Inspector ដែលបញ្ជាក់ setter។
    

```gdscript
# test is initialized to "one", without triggering the setter.
@export var test: String = "one":
	set(value):
		test = value + "!"

func _init():
	# Triggers the setter, changing test's value from "one" to "two!".
	test = "two"

# If someone sets test to "three" from the Inspector, it would trigger
# the setter, changing test's value from "two!" to "three!".
```

ជាលទ្ធផល ការបង្កើតស្គ្រីប ធៀបនឹងឈុត (scene) អាចប៉ះពាល់ទាំងការចាប់ផ្តើមដំណើរការ *និង* ចំនួនដងដែលអេនជីនហៅ setter។

## \_ready ធៀបនឹង \_enter\_tree ធៀបនឹង NOTIFICATION\_PARENTED[](https://docs.godotengine.org/en/stable/tutorials/best_practices/godot_notifications.html#ready-vs-enter-tree-vs-notification-parented "Link to this heading")

នៅពេលបង្កើតឈុតដែលភ្ជាប់ទៅនឹងឈុតដែលបានអនុវត្តដំបូងបំផុត Godot នឹងបង្កើត nodes ចុះក្រោមតាមដើមឈើ (ធ្វើការហៅ `_init()`) និងសាងសង់ដើមឈើចុះក្រោមពីឫស។ នេះបណ្តាលឱ្យការហៅ `_enter_tree()` ធ្លាក់ចុះតាមដើមឈើ។ នៅពេលដែលដើមឈើពេញលេញ លេខស្លាក (leaf nodes) ហៅ `_ready`។ node នឹងហៅវិធីសាស្រ្តនេះម្តងទៀតនៅពេលដែល node កូនទាំងអស់បានបញ្ចប់ការហៅរបស់ពួកវា។ នេះបន្ទាប់មកបណ្តាលឱ្យមានការធ្លាក់ចុះត្រឡប់ក្រោយឡើងលើទៅកាន់ឫសរបស់ដើមឈើ។

នៅពេលបង្កើតស្គ្រីប ឬឈុតឯករាជ្យ (standalone scene) nodes មិនត្រូវបានបន្ថែមទៅក្នុង SceneTree នៅពេលបង្កើតទេ ដូច្នេះគ្មានការហៅចូល `_enter_tree()` បញ្ជាក់ឡើយ។ ផ្ទុយទៅវិញ មានតែការហៅ `_init()` ប៉ុណ្ណោះដែលកើតឡើង។ នៅពេលដែលឈុតត្រូវបានបន្ថែមទៅក្នុង SceneTree ការហៅ `_enter_tree()` និង `_ready()` កើតឡើង។

ប្រសិនបើអ្នកត្រូវការបញ្ជាក់អាកប្បកិរិយាដែលកើតឡើងនៅពេល nodes ក្លាយជាកូនរបស់ node មួយទៀត ដោយមិនគិតពីថាតើវាកើតឡើងជាផ្នែកមួយនៃឈុតចម្បង/សកម្ម ឬអត់នោះទេ អ្នកអាចប្រើការជូនដំណឹង [PARENTED](https://docs.godotengine.org/en/stable/classes/class_node.html#class-node-constant-notification-parented)។ ឧទាហរណ៍ នេះគឺជាផ្នែកខ្លីមួយដែលភ្ជាប់វិធីសាស្រ្តរបស់ node ទៅនឹងសញ្ញា (signal) ផ្ទាល់ខ្លួនលើ node មេដោយមិនបរាជ័យ។ មានប្រយោជន៍សម្រាប់ nodes ដែលផ្តោតលើទិន្នន័យដែលអ្នកអាចបង្កើតនៅពេលដំណើរការ (runtime)។

```gdscript
extends Node

var parent_cache

func connection_check():
	return parent_cache.has_user_signal("interacted_with")

func _notification(what):
	match what:
		NOTIFICATION_PARENTED:
			parent_cache = get_parent()
			if connection_check():
				parent_cache.interacted_with.connect(_on_parent_interacted_with)
		NOTIFICATION_UNPARENTED:
			if connection_check():
				parent_cache.interacted_with.disconnect(_on_parent_interacted_with)

func _on_parent_interacted_with():
	print("I'm reacting to my parent's interaction!")
```
